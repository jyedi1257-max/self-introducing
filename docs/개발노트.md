# 두 단어로 나를 표현하기 — 개발노트

## 한 줄 요약

학생이 **"나는 어떤 사람인가"**를 두 단어로 고르고 그 이유를 말하게 하는 수업용 웹앱. AI 이미지는 거들 뿐, 주인공은 학생이 고른 단어와 이유다.

---

## 1. 프로젝트 개요

### 수업 목적

원 수업 활동의 구조를 웹앱으로 옮긴 것:

```
① 상태·성질 단어 + ② 캐릭터 단어 → 엉뚱한 자기소개
예) 호기심 많은 + 고양이 / 화끈한 + 떡볶이 / 배터리 없는 + 로봇
```

**핵심 원칙**: 이미지 생성 자체가 목적이 아니다. 학생이 *"나는 왜 이 단어를 골랐는가"*를 생각하고 표현하는 것이 목적. AI는 학생 대신 답을 정하는 도구가 아니라, 내가 고른 말을 눈으로 볼 수 있게 만들어 주는 도구.

### 대상

특수교육 수업. 그래서 일반적인 디자인보다 **접근성이 우선**이다.

### 사용자 흐름

```
시작 → 성격/상태 단어 선택 → 캐릭터 단어 선택 → 조합 확인
     → AI 이미지 생성 → 마음에 드는지 판단 (재생성 가능)
     → 두 단어를 고른 이유 작성 → 자기소개 카드 완성
```

한 화면 = 한 과제 원칙.

## 3. 주요 설계 결정

### 개인정보를 최소로 수집한다

저장하지 않는 것: 실제 이름, 학번, 학교명, 사진, 음성, 자기소개 문장, **생성 이미지**.

- 학생 이름은 선택 사항이고 Firebase에 저장하지 않음 (브라우저 메모리에만)
- 생성 이미지는 Storage에 자동 저장하지 않음. 원하면 학생이 직접 내려받음
- Firestore에 남는 건 학생이 제안한 **단어**와 익명 UID뿐

### 장애가 나도 수업은 계속된다

수업용 앱에서 제일 중요한 성질.

- **Firestore 실패** → 앱에 내장된 기본 단어 51개(성격 27 + 캐릭터 24)로 대체
- **AI 실패** → "그림 없이 자기소개 계속하기" 버튼 제공
- **안전 정책 차단** → "이 단어로는 그림을 만들기 어려워요" + 단어 다시 고르기
- 기술적 오류 코드는 학생 화면에 절대 노출 안 함

### 프롬프트는 앱이 만든다

학생이 입력한 두 단어를 그대로 모델에 던지지 않는다. `buildImagePrompt.ts`에서 안전·스타일 지시를 붙인 고정 템플릿으로 감싼다.

- 스타일: friendly whimsical sticker illustration (유아용처럼 과하게 귀엽지 않게)
- 안전: nonviolent, nonsexual, no weapons, no gore
- 금지: 글자, 로고, 워터마크, 실사 인물

### 비용 방어선

- 세션당 이미지 생성 **최대 6회** (보안 제한이 아니라 UX/비용 방어선)
- 생성 버튼 클릭 즉시 disabled, 진행 중 요청 공유로 중복 호출 차단

### 접근성 (특수교육용)

- 기본 글자 20px, 제목 28~32px
- 터치 영역 최소 48px
- 선택 상태를 **색만으로** 표현하지 않음 → 체크 표시 + `aria-pressed` 병행
- 키보드 조작 가능, visible focus (3px)
- 모달 포커스 트랩 + Esc 복귀
- `prefers-reduced-motion` 지원

### 예시 문장을 뺐다 (2026-09-16)

입력칸에 `궁금한 것이 많아서` 같은 예시 답이 흐리게 떠 있으면 **학생이 자기 이유를 찾는 대신 그대로 베껴 쓴다.** 전부 제거.

단, 빈칸 문장 틀은 남김:
```
나는 __________해서 '호기심 많은'을 골랐어요.
```
이건 답을 알려주는 게 아니라 문장을 시작하도록 돕는 장치라 유지.

## 4. 삽질 기록 (재현 방지용)

> 이 섹션이 이 노트의 핵심 가치. Firebase + Gemini 조합에서 며칠 날린 함정 3개.

### 함정 1 — 이미지 생성은 무료 요금제에서 아예 불가

**증상**
```
429: Quota exceeded for metric:
     generativelanguage.googleapis.com/generate_content_free_tier_requests,
     limit: 0, model: gemini-3.1-flash-image
```

**원인**: `limit: 0`. 텍스트 생성은 무료 티어가 있지만 **이미지 생성 모델은 무료 할당량이 0**. 인증 방식(OAuth / API 키 / 서비스 계정)을 바꿔도 소용없다. 할당량은 "누가 요청했나"가 아니라 **"프로젝트가 결제 계정에 연결됐나"**에 붙는다.

**해결**: Blaze(종량제) 업그레이드 필요.

---

### 함정 2 — GCP $300 크레딧은 Gemini Developer API에 안 먹힌다

**증상** (Blaze 연결 직후)
```
429: Your prepayment credits are depleted.
     Please go to AI Studio at https://ai.studio/projects
```

**원인**: Google Cloud 무료 체험 $300 크레딧과 Gemini API의 **선불 크레딧은 별개 주머니**다. 2026년 3월부터 Gemini Developer API가 $300 무료 체험 대상에서 제외됨.

**핵심 발견**: 같은 Gemini 모델인데 **들어가는 문이 두 개**다.

```
Gemini Developer API (GoogleAIBackend)  → 선불 크레딧 필요      ❌
Vertex AI / Agent Platform (VertexAIBackend) → Cloud Billing 청구 ✅ 크레딧 적용됨
```

Firebase 공식 문서 인용:
> 크레딧은 Gemini Developer API 비용에는 사용할 수 없지만, Agent Platform Gemini API(구 Vertex AI)와 대부분의 유료 Firebase·Google Cloud 서비스에는 사용할 수 있습니다.

**해결**: `src/firebase/ai.ts`에서 백엔드를 `GoogleAIBackend` → `VertexAIBackend`로 교체. 환경변수 `VITE_AI_BACKEND`로 선택 가능하게 만듦 (기본값 `vertex`).

```ts
const backend =
  AI_BACKEND === 'google' ? new GoogleAIBackend() : new VertexAIBackend(AI_LOCATION);
```

→ **이걸로 이미지 생성 성공.**

---

### 함정 3 — reCAPTCHA Enterprise API가 꺼져 있으면 App Check가 400 (미해결)

**증상**
```
POST .../exchangeRecaptchaEnterpriseToken → 400
→ AppCheck: 400 error (appCheck/initial-throttle)
→ AI 호출 401: Firebase App Check token is invalid
```

**혼란스러웠던 점**: 설정이 전부 정상으로 보였다.
- reCAPTCHA 키 도메인에 `self-introducing.web.app` 등록됨 ✅
- App Check 공급자 = reCAPTCHA Enterprise ✅
- 사이트 키 일치 ✅
- 브라우저의 reCAPTCHA 토큰 발급(`reload?k=...`)은 **200 성공** ✅

**단서**: reCAPTCHA 키 상세 화면에서
```
상태: 미완료  ("키가 토큰은 요청하지만 점수(평가)를 요청하지는 않고 있습니다")
통합: 프런트엔드 ✅ / 백엔드 ⚪ Set up
```
→ 토큰은 받는데 **채점이 한 번도 일어난 적 없다**는 뜻.

**원인**: `recaptchaenterprise.googleapis.com` API가 **사용 중지 상태**였음. Firebase가 토큰을 채점하려 해도 API가 꺼져 있어 실패.

**조치**: API 사용 설정함. 하지만 활성화 직후에도 여전히 400.

**현재 상태**: **미해결.** App Check 적용(enforce)을 해제해서 우회 중.

**교훈**: 콘솔 어디에도 "API를 켜세요" 안내가 없고 오류는 400뿐이라 추적이 어려웠다. 로컬에서는 **디버그 토큰**이 reCAPTCHA를 통째로 건너뛰기 때문에 이 문제가 배포 전까지 드러나지 않음. → **배포 주소에서 반드시 별도 검증할 것.**

## 6. 명령어 치트시트

```bash
# 개발
npm install
npm run dev              # localhost:5173

# 검증
npm run typecheck
npm run test:rules       # Firestore 규칙 에뮬레이터 테스트 14개

# 배포
npx firebase login
npx firebase use --add   # self-introducing 선택
npm run deploy           # build + hosting/firestore 배포

# 단어 시드 (서비스 계정 키 필요)
GOOGLE_APPLICATION_CREDENTIALS=서비스계정.json \
FIREBASE_PROJECT_ID=self-introducing \
npm run seed
```

### Windows 초기 설정 메모

- PowerShell에서 npm 실행 불가 시:
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` → `Y`
- 배포 후 "Site Not Found"가 뜨면 **브라우저 캐시**. 시크릿 창(`Ctrl+Shift+N`)으로 확인.
